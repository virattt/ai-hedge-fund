# FOMO (fomo.family) identity-resolution research -- 2026-09-19

*Agent report, saved verbatim. Read-only web research; claims marked CONFIRMED were fetched live by the agent on the date above and have not been re-verified by the orchestrating session.*

## VERDICT
Resolvable, cheap, and mostly one-directional in confidence. FOMO's own site blocks crawlers from profile pages (robots.txt disallows `/profile/`, `/user`, `/u/`), so there's no official public API and no sitemap listing of profiles -- but this didn't stop a small ecosystem of unofficial resolvers (fomoapi.io, fomolens.app, fomoscan.sh, getfomoapi.fun) from reverse-engineering FOMO's app backend and offering handle<->wallet lookups for free or near-free. Separately, and more interestingly, FOMO's Hyperliquid perps flow through two on-chain "builder codes" whose fill data is published by Hyperliquid itself, unauthenticated, for free -- verified live (HTTP 200, real bytes) -- which lets you bypass FOMO's robots.txt entirely and get every FOMO perps trader's real wallet straight from Hyperliquid's own infrastructure. What you get is strong on the wallet<->account binding (FOMO's embedded wallet is generated by the platform for that account -- operationally as solid as it gets, though not a user-signed cryptographic proof) and weak/self-reported on the X-handle link and on "this wallet = this named KOL/whale," which nobody has bulk-verified. Whether naming any of this changes the trading signal is UNVERIFIED for FOMO/Hyperliquid specifically -- only thin, non-academic, single-source blog claims exist on KOL copy-trading fade generally; no study was found matching the project's prior "positive-then-negative, worst for big-following self-experts" pattern applied to this platform.

## 1. What FOMO itself exposes

**CONFIRMED:**
1. `robots.txt` at fomo.family explicitly disallows crawler access to `/profile/`, `/user`, `/u/`, `/token`, `/prices/`, `/export-key`, `/verify-token`, and others, while granting Twitterbot unrestricted access; it points to `https://fomo.family/sitemap.xml`. (fetched directly, 2026-09-19)
2. `sitemap.xml` lists 162 URLs -- homepage, `/blog`, `/answers/*` (56 FAQ pages), `/blog/learn/*` (59 guide pages), `/terms`, `/privacy-policy`, `/affiliates`, `/careers`, `/prices`. **Zero profile, user, or leaderboard URLs are listed.** (fetched directly)
3. FOMO does not publish an official developer API or docs -- confirmed by direct search and by an independent third-party API cataloguer. ([api-evangelist/fomo apis.yml](https://github.com/api-evangelist/fomo/blob/main/apis.yml))
4. FOMO wallets are Privy-powered embedded self-custodial wallets created automatically at signup (email or Apple ID, no seed phrase, 2-of-3 Shamir key split) -- so a user's wallet is bound to their account by the platform itself, not by a separate proof step the user performs. ([Privy blog on fomo](https://privy.io/blog/turning-trading-into-a-social-experience-with-fomo))
5. FOMO's Privacy Policy (fetched directly) covers CCPA and Virginia CDPA deletion/opt-out rights explicitly, and acknowledges public posting. **It does not mention GDPR anywhere.** FOMO Labs, Inc. is a New York company.
6. Terms of Service exist at fomo.family/terms (seen via search extract only).

**UNVERIFIED / not attempted:**
- No live `/profile/{handle}` page was fetched, in deference to robots.txt's explicit `Disallow`. What a profile displays is evidenced only indirectly, via the third-party resolvers below.
- Whether profile visibility is opt-in or default-on is not stated anywhere found. Practical behavior looks like "public to anyone with the link or handle, but not search-indexed" -- an inference, not a confirmed policy.
- Whether X-handle linking on FOMO is OAuth-verified vs. typed into a bio is UNVERIFIED.

## 3. Cheapest sound self-rolled approach -- the strongest finding

**CONFIRMED, verified live by the agent:**
1. FOMO's Hyperliquid perps run through two on-chain builder codes, found in DefiLlama's open-source fee adapter (raw source fetched):
   - `fomo-perps`: `0xb838e4d1c8bcf71fa8e63299d5aa3258c83d6adb`
   - `fomo-social-trading-perps`: `0x2a2b6b093a9813fbd8cddae800c3d17d46460d17` (start date 2026-06-05, matching FOMO's June 2026 perps launch)
   ([DefiLlama/dimension-adapters factory/hyperliquid.ts](https://github.com/DefiLlama/dimension-adapters/blob/master/factory/hyperliquid.ts))
2. Hyperliquid publishes daily per-builder fill data, unauthenticated, at `https://stats-data.hyperliquid.xyz/Mainnet/builder_fills/{builder_address}/{YYYYMMDD}.csv.lz4` ([builder-codes docs](https://hyperliquid.gitbook.io/hyperliquid-docs/trading/builder-codes)). Both FOMO builder addresses for 2026-09-18 returned **HTTP 200** with real payload (618KB social-trading-perps, 26KB legacy) -- no auth, no key.
3. So the complete set of on-chain wallet addresses that traded perps through FOMO is available directly from Hyperliquid, for free, with no FOMO-side dependency.

**Effort/cost:** (1) pull daily builder_fills CSVs for both addresses; (2) reverse-resolve each distinct wallet to a FOMO handle/X-link via fomoapi.io's free tier or fomolens.app. Per-identity cost ~$0 at research scale; $49.99+/mo only past free-tier volume.

**UNVERIFIED:** the CSV column headers were not inspected (time cap), so the exact fields present are unconfirmed.

## 4. Realistic coverage -- structural, not measured

- **PLATFORM-ATTESTED (operationally strong, not a user-signed proof):** handle<->wallet binding. Likely near-universal for active traders, but unmeasured.
- **SELF-CLAIMED/PLATFORM-LINKED (weaker):** X/Twitter handle, returned "when linked." No adoption rate published anywhere.
- **INFERRED (weakest, manual):** "this FOMO wallet/handle is a known KOL or whale." No bulk automated cross-walk found.

**No number exists anywhere for "X% of FOMO's top N traders resolve to a name."** Producing one fits inside fomoapi.io's free tier but was not run.

## 5. Does naming change the signal -- thin

- "~42% 30-day win rate across 457 scored Solana KOL wallets" and "~48% of copy-trading followers are profitable" are single-source content-site claims, not peer-reviewed or exchange-published. Directional color only.
- No study found measuring FOMO or Hyperliquid-vault follower returns against KOL-linked wallets, follow or fade.
- Nothing corroborates or contradicts the project's prior finding as applied to this platform.

**The named layer's predictive value is untested for this platform. Don't assume the fade pattern transfers without measuring it here first.**

## 6. Where the line sits (owner's decision)

Reading and republishing what a FOMO user put in their own public profile (handle, self-linked X, FOMO's own verified flag) is republishing the user's own speech. Taking a wallet address that never touched FOMO's public surface and attributing it to a named person via inference/clustering generates a new fact about someone who never opted into disclosure. Recommended line: store and act on links the platform or the user published themselves; do not store or publish a wallet->real-name attribution that rests on inference alone; never persist raw PII (email, phone, KYC). GDPR is unaddressed by FOMO's own policy; a downstream build storing EU-person wallet<->identity links would need its own basis.

## Build recommendation

1. Pull FOMO's Hyperliquid builder-fills CSVs (free, two known addresses) for the wallet-level perps population.
2. Reverse-resolve those wallets plus a top-N-by-volume list through fomoapi.io's free tier or fomolens.app.
3. Before trusting the named layer as a trading input, measure follow-vs-fade returns on FOMO/Hyperliquid data specifically.

Cash cost: $0-$50/mo. Effort: a few hours for the pull + join; the return-measurement pass is the part worth gating a trading decision on.
